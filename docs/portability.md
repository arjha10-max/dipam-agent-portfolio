# Portability

This document explains what stays fixed in the DIPAM agent operating model and what changes by client, category, market, or data environment. It uses the two synthetic sample briefs—Vividance functional hydration and DermaNova barrier-repair skincare—to show portability.

## 1. Portability thesis

The operating model should stay stable even when the category changes. The brief, evidence, audience motivations, claims, retail paths, creative system, and measurement inputs change. The workflow, gates, state model, templates, and human accountability controls remain consistent.

That makes the system useful as an agency platform pattern: it creates repeatable structure without forcing every campaign into the same strategy.

## 2. What stays fixed

| Component | Why it stays fixed |
|---|---|
| Brief-driven start | Every campaign needs a clear input and readiness decision |
| Stage sequence | Intake → Data → Identity → Personalization → Activation → Measurement prevents premature execution |
| Human gates | Approval accountability should not vary by brand |
| `STATE.md` shared state | Decisions, assumptions, approvals, blockers, and escalations need one source of truth |
| Required output structure | Standard outputs make work reviewable and reusable |
| `So what / Decision needed / Assumptions and confidence` | Forces synthesis and honest uncertainty |
| Synthetic and source labelling | Protects trust and separates evidence from assumption |
| Privacy-by-design controls | Consent, minimization, and clean-room principles apply across categories |
| MPA gate | Activation should not begin without commercial authorization |
| Pre-flight QA gate | Launch readiness always needs human confirmation |
| No-invented-performance rule | Measurement integrity applies to every campaign |
| Escalation matrix | Risk handling should be consistent across clients |

## 3. What changes by client or campaign

| Variable | What changes |
|---|---|
| Brand and product truth | Product attributes, proof points, claims, pack architecture |
| Category definition | Competitors, substitutes, occasions, barriers, retail behavior |
| Audience motivations | Jobs to be done, psychographics, triggers, objections |
| Data environment | First-party assets, consent status, clean-room access, retailer reporting |
| Market requirements | Privacy, language, claims, media availability, retailer norms |
| Budget and timing | Scale, phasing, reach, vendor selection, production scope |
| Creative system | Territories, tone, formats, claims copy, localization |
| Media mix | Channel roles, vendor selection, flighting, budget allocation |
| Activation requirements | IO structure, creative specs, tags, retail readiness, QA checks |
| Measurement | KPI definitions, reporting cuts, test design, data availability |

## 4. Vividance versus DermaNova

| Dimension | Vividance functional hydration | DermaNova barrier-repair skincare | What portability demonstrates |
|---|---|---|---|
| Category | Functional beverage | Skincare | Same workflow handles different category evidence |
| Core tension | Hydration and energy-drink trade-off | Barrier care versus routine complexity | Identity adapts to different motivations |
| Product proof | Electrolytes, magnesium, L-theanine | Ceramides, glycerin, niacinamide | Message architecture changes; template stays fixed |
| Claims risk | Functional and cognitive-adjacent language | Cosmetic and skin-condition language | Claims guardrails adapt to category rules |
| Purchase behavior | Grocery, convenience, club, ecommerce | Beauty specialty, mass retail, ecommerce | Channel and retail evaluation changes |
| Repeat KPI | 90-day repeat purchase | 120-day replenishment | Measurement adapts to product usage cycle |
| Creative emphasis | Occasion-led hydration ritual | Ingredient-led education and reassurance | Creative territories change; modular system remains |
| Retail media dependency | Retailer reset and availability | Product-page readiness and distribution | Activation adapts to different retail dependencies |
| Sensitive targeting risk | Health or performance inferences | Medical skin-condition inferences | Consent matrix and exclusions remain essential |
| Data assets | Beverage category buyers, retail clean room | Beauty buyers, ecommerce behavior, retail clean room | Signal map changes; governance remains |

## 5. How Sample Brief 2 proves portability

DermaNova uses the same:

- Intake extraction fields
- Data research structure
- Competitor and price-pack logic
- 1 CORE + 2 GROWTH audience architecture
- Audience-signal and consent matrices
- Integrated creative and media approval pack
- Three budget scenarios
- MPA and pre-flight gates
- Measurement export rule
- Optimization recommendation structure

But it changes the strategic substance:

- Category competitors and substitutes
- Audience jobs and barriers
- Claims guardrails
- Retailer behavior
- Creative education requirements
- Replenishment window
- Measurement feasibility

This shows that the system is portable because the operating model is stable while the campaign-specific inputs remain flexible.

## 6. Client adaptation checklist

Before using the workflow with a different client or category, update:

1. Brief template fields and approval roles
2. Category definition and competitive set
3. Claims and compliance guardrails
4. Data inventory and consent matrix
5. Audience architecture if the brief explicitly requires more or fewer profiles
6. Channel and vendor evaluation criteria
7. Retailer and distribution dependencies
8. Creative production requirements
9. Measurement KPI definitions and reporting cuts
10. Escalation thresholds and accountable owners

## 7. Scaling principle

Standardize the workflow, not the answer. The agent should make campaigns easier to brief, structure, review, activate, and learn from. It should not collapse distinct brands into generic recommendations.
